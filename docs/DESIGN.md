> 本文件是**可修改的活文档**：视觉约定以本文件为准，代码侧只落地在 `frontend/src/theme/` 一处。
> 修改本文件后，只需同步 token 文件即可全局生效，不应出现散落各页面的硬编码色值。
>
> **本次改版（2026-09-24，P1）**：从"默认 Ant Design 配色"升级为
> **浅色企业级专业风为主 + 品牌 / 智能感点缀**。风险语义色、决策动作色、
> 布局尺寸（三栏、卡片内边距、状态文案）全部保持不动 —— 它们是 P0/P1 功能
> 的验收口径，不能因为换肤而跟着变。未被本文件覆盖的场景，才退回 AntD 默认值。

## 1. 设计原则

1. **信息结构优先于视觉**：先把信息层级、分区、交互路径理清，再谈配色与动效；"先好看"的前提是"先能用"。
2. **风险语义色唯一且稳定**：低/中/高与四种决策动作的颜色在全系统内不得改变含义（这是风控产品的业务色，不是装饰色）。
3. **状态完整**：每个数据区块必须具备加载态、空态、错误态、成功反馈，禁止"白屏即无数据"。
4. **密度适中**：风控系统以表格与图表为主，默认紧凑但不拥挤，一屏尽量少滚动。
5. **浅是主基调，深有分寸**：全站浅色（明度 ≥ 96%）；品牌与智能感只落在导航、登录、图表强调、模型 / AI 反馈这一组固定位置，不让颜色"到处开花"。
6. **智能感 ≠ 加机器猫**：本项目的"AI"是**规则 + 模型的论证过程**（特征 → 名单 → 规则 → 模型 → 决策），因此智能感的视觉是"看得到的推理链"，而不是拟人化形象。

## 2. 色彩

### 2.1 品牌色（本次新增，全站唯一）

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| brand-600 主色 | `#1E5EFF` | 主按钮、链接、选中项、关键交互锚点 |
| brand-500 hover | `#2F6DFF` | 悬停、过渡态 |
| brand-700 active | `#1848D1` | 按下、深层选中 |
| brand-50 底 | `#EFF4FF` | 品牌浅底 tag / 横条 |
| brand-gradient | `#1E5EFF → #7C3AED`（45°） | **唯一**的 SaaS 渐变，仅用于 Logo、登录页主视觉、SSE 实时滚屏顶条这类锚点 |

**为什么是这个蓝**：默认值 `#1677ff` 是 AntD 的品牌色，直接沿用会把整个系统读成"又一
个 antd 项目"。本系统决策链路可视化是最重要的差异化点，因此品牌色相偏冷、饱和度
更高（`#1E5EFF`），让"决策链路"与"普通数据"在视觉里天然分成两种密度。

### 2.2 智能感点缀（克制：全站只有一个位置允许渐变）

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| ai-600 | `#7C3AED` | 模型相关内容：模型页标识、模型贡献度 Top5 标题、AI 推理链标签 |
| ai-50 | `#F5F3FF` | 模型贡献卡片的底色 |
| ai-发光（Glow） | `radial(closest-side, rgba(124,58,237,0.12), transparent)` | 模型页 / 链路回溯页的极弱底光，营造"有模型在起作用"的暗示 |

**不做的三件事**：① 不让紫色出现在风险语义里（紫 ≠ 风险）；② 不做≥3 色的渐变；
③ 不把智能感做成动画人物或聊天框（本系统的 AI 是论证链，不是拟人对话）。

## 3. 字体与字号

字体栈：
`Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", -apple-system, "Segoe UI", sans-serif`
（Inter 负责数字与西文的"工程感"，Noto Sans SC 负责中文正文）

数字与编码类字段（案件号、事件号、IP、设备ID、分数、金额、权重、哈希值）：
`"IBM Plex Mono", "JetBrains Mono", Consolas, monospace`
（Plex Mono 的 0 有斜杠、1 有底衬，能显著区分 O/0、l/1 —— 这是风控场景的高频痛点）

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 20px | 600 | 页面顶部 |
| 卡片标题 | 16px | 600 | 卡片、区块头 |
| 正文 | 14px | 400 | 表格、表单、描述 |
| 辅助 | 12px | 400 | 说明、时间戳、次要标签 |
| 指标数值 | 30px | 600 | 大盘指标卡（用 Plex Mono） |

中文标题不加粗到 700：Noto Sans SC 的 600 与 Inter 的 600 在视觉上字重等价，
混排时统一用 600；避免"中文 700、西文 600"的错乱。

## 4. 间距与栅格

- 间距以 **4px** 为基础单位：`4 / 8 / 12 / 16 / 24 / 32`。
- 页面内容区内边距 `24px`；卡片间距 `16px`；卡片内边距 `16px 20px`；表单项纵向间距 `16px`。
- 主框架：左侧导航宽 `220px`（折叠 `64px`）、深色底（§2.5），顶栏高 `56px` 浅色，内容区自适应。
- 审核工作台三栏：左 `320px` ｜ 中 自适应（min 480px）｜ 右 `400px`；中栏与右栏在 <1440px 视口下允许折叠为 Drawer。

---

## 5. 布局规范

- 每页结构：`页面标题 + 面包屑` → `筛选/操作区` → `内容区`。
- 卡片统一圆角 `8px`，阴影 `0 1px 2px rgba(15,23,42,0.04)`（**不用** `rgba(0,0,0,*)` 这种通用黑阴影 —— 中性色里带一点蓝相）；
  悬浮层（Drawer / Modal / 下拉）允许 `0 4px 16px rgba(15,23,42,0.08)`，但不叠加更多。
- 大盘采用 24 栅格：指标卡 `6` 列（4 张一行），趋势图 `16` 列 + 分布图 `8` 列，
  排行 `12` 列 + 滚屏 `12` 列。
- 表格默认 `size="middle"`，分页 `20 / 50 / 100`；长文本省略并支持 Tooltip。
- **行为动线**：高危操作（拦截、删除、归档）永远放最右、danger 色；
  确认类放中间；取消类放最左。助手与危险按钮在视觉上拉开 ≥24px 距离。

## 6. 组件使用约定

| 场景 | 约定 |
| --- | --- |
| 风险等级/动作 | 统一 `Tag`，使用 §2.3 语义色板，文案固定为"低/中/高风险""放行/挑战/人审/拦截" |
| 数值指标 | `Statistic`，数值 30px + Plex Mono，单位与说明置于下方 12px 次文本 |
| 详情字段 | `Descriptions` 两列（窄屏一列），label 次文本色 |
| 二次确认 | `Modal.confirm`，危险操作按钮使用 danger 样式 |
| 表单 | `Form` 垂直布局，必填标星，校验信息即时展示 |
| 条件编辑器 | 树形节点 `与/或/非 + 条件行`，条件行 = 字段下拉 + 运算符下拉 + 值输入，未知字段标红 |
| 实体图谱 | ECharts `graph` 力导向，容器高度 `420px`，节点按风险等级取色，边按关系类型区分虚实 |
| 链路回溯 | `Steps` 竖向五步（特征 → 名单 → 规则 → 模型 → 决策），每步可被点开看明细 |
| 状态标签 | 案件状态：待审 `gold`、审核中 `blue`、已处置 `green`、已归档 `default`、已关闭 `default` |
| 模型贡献 | 标题带 `ai-600` 左侧 3px 色条；明细行用 Plex Mono 列分数，正贡献 → `danger` 红，负贡献 → `success` 绿 |
| 品牌 Logo | 深蓝导航底 `#0B1220` 上，Logo 图形用 `#1E5EFF → #7C3AED` 渐变，文字保持 `#FFFFFF` |

## 7. 状态反馈规范

| 状态 | 表现 |
| --- | --- |
| 加载 | 骨架屏 `Skeleton`（卡片/表格）或 `Spin`（局部） |
| 空态 | `Empty`，附一句可执行建议（如"暂无案件，可在仿真页注入事件"） |
| 错误 | `Result status="error"`，给出原因与重试按钮 |
| 成功 | 顶部 `message.success`，措辞具体（如"已拦截订单 ORD-2026-0001"） |
| 实时断线 | 顶栏常驻提示条"实时推送已断开，正在重连…"，恢复后提示"已恢复" |

## 8. 文案与交互细节

- 全站中文，动词前置："接手案件""提交处置""导出名单"。
- 危险操作确认文案模板：`确定要{动作}吗？该操作将{影响后果}，且会记入审计日志。`
- 批量导入反馈：成功 N 条 / 失败 M 条，失败行给出原因并可下载失败明细。
- 时间显示统一 `YYYY-MM-DD HH:mm:ss`（Asia/Shanghai），悬浮显示相对时间。
- 分数与金额统一用 Plex Mono 展示，对齐到小数点后 2 位；权重带符号（如 `+1.290` / `-0.769`）。

## 9. 智能感点缀的边界（本次必须写死）

| 位置 | 可以做 | 禁止做 |
| --- | --- | --- |
| 登录页 | brand-gradient 点缀 + 卡片轻阴影 + 一句"决策链路已就绪"的系统状态行 | 全屏渐变、拟物插画、打字机欢迎语 |
| 深色导航 | brand-gradient 的 Logo、hover 时 2px 左条 | 每个菜单各自配色、彩虹图标 |
| 大盘 SSE 滚屏 | 顶部 2px brand-gradient 横条 + 曲线用渐变描边 | 闪烁动画、数字滚动特效 |
| 模型页 / 链路回溯 | ai-50 底 + `rgb(124,58,237)` 强调线 + 环形"模型已启用"徽标 | 大面积紫色底、紫色按钮、AI 聊天框 |
| 案件工作台 | 证据链卡片用 `ai-600` 左色条标出"模型关注点 Top5" | 给模型结论加"AI 全部掌握"的语气 |

**唯一允许的动效**（除必要的过渡）：
- 登录页卡片入场一次（opacity + translateY 6px，300ms）；
- SSE 滚屏新条目入场一次（opacity + translateY 4px，200ms）；
- `prefers-reduced-motion` 时全部停止。
